# APK Static Analysis Agent (AegisAI)

A simple, working version of the **Static Analysis Agent** described in the
AegisAI synopsis. Upload a real Android `.apk` file and it will inspect:

- Package name, app name, version, min/target SDK
- Requested permissions (flagging sensitive ones like SMS, Accessibility,
  Overlay, Camera, Location, etc. with a severity)
- Manifest flags: debuggable, allowBackup, exported activities
- Signing certificate issuer/subject
- **SHA-256 hash lookup against VirusTotal** (Threat Intelligence Agent) —
  flags files already known to be malicious/suspicious by security vendors
- An overall Risk Score (0-100) and Risk Label (LOW/MEDIUM/HIGH), combining
  both static findings and threat intelligence
- An optional plain-English explanation generated by a local Ollama model

**The APK is never installed or executed** — only its manifest, permissions,
certificate, and file hash are inspected (this is what makes it "static"
analysis).

## Architecture (mini multi-agent pipeline)

```
Upload APK
    |
    v
Orchestrator Agent (orchestrator.py)
    |
    +--> Static Analysis Agent (analyzer.py)   -> permissions, manifest, certificate
    |
    +--> Threat Intelligence Agent (threat_intel.py) -> SHA-256 + VirusTotal lookup
    |
    v
Combined findings -> Risk Scoring (report.py) -> GenAI explanation (llm.py, via Ollama)
    |
    v
Final Report
```

## Setup (Windows PowerShell)

```powershell
cd apk_static_agent
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```

## Set your VirusTotal API key (free account at virustotal.com)

```powershell
$env:VT_API_KEY="paste-your-key-here"
```

If this is not set, the Threat Intelligence step will still run but simply
note that it was skipped — the rest of the app keeps working.

## Before running: make sure Ollama is available (optional but recommended)

1. Open Docker Desktop and make sure it says "Engine running"
2. Make sure the ollama container is started:
   ```powershell
   docker start ollama
   ```
3. Tell this app which model to use (must match what you pulled earlier):
   ```powershell
   $env:OLLAMA_MODEL="llama3.2:3b"
   ```

If Ollama isn't running, the app still works fine — it just won't show the
AI explanation section.

## Run the app

```powershell
uvicorn backend.main:app --reload
```

Then open: http://127.0.0.1:8000

Upload any `.apk` file (e.g. a small app downloaded from f-droid.org) and
click "Analyze APK".

## How this maps to the AegisAI synopsis

This is a working, simplified prototype of the **Static Analysis Agent**
block from the AegisAI architecture diagram: it decompiles/inspects the APK
(via Androguard instead of full JADX/Apktool), checks the manifest for
dangerous permission combinations, inspects the signing certificate, and
produces findings + a risk score — the same role it plays in the larger
multi-agent AegisAI pipeline.

## Added investigation pages

The original AegisAI scanner interface is preserved. The enhancement adds separate pages that consume the latest investigation saved by the existing scanner:

- `/threat-intel` — Threat Intelligence Agent
- `/network` — Network Analysis Agent / IOC workspace
- `/sandbox` — Sandbox Agent workspace (safe, non-executing integration page)
- `/codegraph` — CodeGraph evidence view
- `/verifier` — Risk Scoring + Verifier / adaptive re-task view
- `/report` — consolidated investigation report

The existing Static Analysis and GenAI Reasoning pages remain unchanged in their core workflow.
